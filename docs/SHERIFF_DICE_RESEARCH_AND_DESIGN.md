# پژوهش و طراحی «تاس شریف»

## هدف

«تاس شریف» یک بازی سالن زنده با **Sheriff Coin کاملاً مجازی و غیرقابل‌نقد** است. همهٔ کاربران نتیجهٔ مشترک هر راند را می‌بینند، اما می‌توانند پیش‌بینی متفاوتی (کمتر/بیشتر و آستانهٔ متفاوت) ثبت کنند. نتیجه، شرط، تسویه و موجودی همگی روی PostgreSQL/Supabase و به‌صورت server-authoritative محاسبه می‌شوند.

این طراحی عمداً از dark pattern، Auto-bet، پیام‌های «جبران باخت»، Near-miss جعلی و بات پنهان استفاده نمی‌کند. هیجان بازی از زمان‌بندی راند مشترک، انتخاب احتمال/ضریب و امکان راستی‌آزمایی می‌آید، نه از فریب کاربر.

## پژوهش مرجع

در تاریخ ۲۰۲۶-۱۰-۲۲ مخازن عمومی GitHub مرتبط بررسی شدند:

1. [`jdleo/provably-fair-dice`](https://github.com/jdleo/provably-fair-dice) — MIT؛ نمونهٔ آموزشی React/Next با تعهد بذر، nonce، تاریخچهٔ Verify و فرمول `winChance = 99 / multiplier`. نکتهٔ مفید: نمایش صریح شانس و house edge. نکتهٔ قابل بهبود: تولید نتیجه با modulo ساده و checklist تولید که خودش هنوز انجام نشده است.
2. [`AndreMiras/etheroll`](https://github.com/AndreMiras/etheroll) — MIT؛ رابط قدیمی بازی تاس روی قرارداد هوشمند. پروژهٔ بالادستی تعطیل شده است؛ فقط برای شناخت الگوی Roll Under و نمایش احتمال بررسی شد، نه برای کپی کد یا معماری بلاکچین.

کد «تاس شریف» مستقل و متناسب با معماری موجود پروژه نوشته شده است. از منابع بالا فقط مفاهیم عمومی احتمال، تعهد/افشای بذر و نمایش شفاف ضریب استفاده شده‌اند.

## قوانین نهایی

- هر راند ۸ ثانیه پنجرهٔ شرط و ۳٫۵ ثانیه نمایش نتیجه دارد.
- نتیجه عدد صحیح `0..9999` است و در UI به شکل `0.00..99.99` نمایش داده می‌شود.
- هر بازیکن در هر راند فقط یک شرط دارد.
- مبلغ: ۱۰ تا ۵۰۰ شریف‌کوین.
- هدف: `2.00..98.00`.
- `UNDER`: برد وقتی `roll < target`.
- `OVER`: برد وقتی `roll >= target`.
- شانس بر حسب basis point:
  - UNDER: `target`
  - OVER: `10000 - target`
- ضریب پرداخت (صدم): `floor(990000 / chanceBps)`.
- پرداخت: `floor(stake * multiplier / 100)`.
- RTP نظری حداکثر ۹۹٪ و لبهٔ خانه ۱٪ است؛ گردکردن رو به پایین می‌تواند RTP واقعی هر انتخاب را اندکی کمتر کند.

## Provably Fair

1. پیش از شروع شرط، سرور ۳۲ بایت تصادفی می‌سازد.
2. فقط `SHA256(serverSeed)` همراه salt راند منتشر می‌شود.
3. نتیجه از ۵۲ بیت بالای `HMAC-SHA256(key=serverSeed, message=salt)` ساخته می‌شود:

```text
r = first52Bits(hmac)
roll = floor(r * 10000 / 2^52)
```

4. پس از بسته‌شدن شرط، seed فاش می‌شود.
5. فرانت‌اند با همان الگوریتم مستقل نتیجه و hash را دوباره محاسبه می‌کند.

استفاده از scale روی فضای ۵۲ بیتی به‌جای `% 10000`، اختلاف اندازهٔ bucketها را به حداکثر یک مقدار از `2^52` محدود می‌کند و با SQL عددصحیح قابل بازتولید است.

## امنیت و اقتصاد

- RLS روشن و دسترسی مستقیم browser به همهٔ جدول‌ها بسته است.
- lifecycle helpers از `PUBLIC/anon/authenticated` revoke شده‌اند.
- فقط `dice_get_state`، `dice_place_bet` و verifier عمومی grant می‌شوند.
- debit و payout فقط از `coins_grant` عبور می‌کنند و ledger append-only دارند.
- قفل singleton هر راند، بستن پنجره و ثبت شرط را serializable می‌کند.
- سقف باخت روزانه بین stakes، انفجار و تاس مشترک است.
- بن `stakes/global`، کیف پول freeze، maintenance و rate limit اعمال می‌شوند.
- Broadcast فقط invalidation عمومی می‌فرستد؛ state و wallet از RPC canonical خوانده می‌شود.
- فهرست سالن فقط شرط کاربران واقعی را نشان می‌دهد؛ بات پنهان وجود ندارد.

## کنترل مصرف

- Auto-bet وجود ندارد.
- سود/زیان و حجم شرط روزانه همیشه دیده می‌شود.
- سقف باخت روزانه سمت سرور قابل دور زدن نیست.
- بعد از ۲۰ دقیقه، یادآور استراحت نمایش داده می‌شود.
- متن UI استقلال راندها و مجازی/غیرقابل‌نقد بودن سکه را روشن می‌کند.
